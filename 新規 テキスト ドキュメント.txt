你嘅擔憂係絕對正確而且非常有安全意識！喺 Cloud 架構入面，呢種駭客行為叫做「Billing Attack（帳單攻擊）」，專門針對 Pay-as-you-go 嘅系統狂刷 API，目的就係想搞到開發者收到天價月結單。

如果你打算升級 Firebase Blaze Plan，為咗保護自己個荷包，你必須要學識以下嘅「防禦」同「應急」措施。Set 好晒安全網先升級，就可以高枕無憂！

🛡️ 預防措施：點樣阻止駭客狂刷 API？
1. 啟用 Firebase App Check（最強防護盾）
呢個係 Firebase 官方提供嘅防護機制（Web 端通常結合 reCAPTCHA v3）。啟用之後，Firebase 會驗證每一個 Request 係咪真係由你指定嘅網域（例如你個 vercel.app）發出嚟。

如果駭客寫 Python 腳本、用 Postman 或者透過 Terminal 狂打你個 Database，App Check 會直接喺外圍 Block 晒佢哋。

重點：被 App Check 攔截嘅無效 Request 係唔會計入你嘅 Database 讀寫收費。

2. 收緊 Firebase Security Rules（資料庫守衛）
絕對唔好將 Database 打開做任人讀寫（例如 ".write": true）。你應該喺 Rules 入面寫明：

只容許寫入特定嘅 Data（例如 payout 必須係數字，不能大過某個合理數值）。

限制字串長度，防止駭客惡意塞入幾百 MB 嘅垃圾文字去刷爆你嘅 Storage 同 Download 流量。

🚨 監控及應急煞掣：見到異常點算？
3. 設定預算警告（Budget Alerts）
Firebase 嘅計費背後其實係連住 Google Cloud Platform (GCP)。你綁咗信用卡之後，第一件事就係去 GCP Billing 後台設定「預算警告」。

例如，你設定每個月預算上限為 $1,000 円。

你可以 Set 當洗費達到 50%、90%、100% 嗰陣，系統要即刻彈 Email 甚至手機通知畀你，確保你唔會到月尾收到張單先如夢初醒。

4. 終極應急煞掣：隨時可以即刻 Cut！
如果你真係收到 Email 警告，發現 Database 被人惡意攻擊，你絕對可以即刻煞掣，有兩個最快嘅做法：

方法 A：即時降級 (Downgrade)
入去 Firebase 後台，將個 Plan 即刻轉返做 Spark（免費版）。系統會瞬間恢復「100人連線限制」同「10GB 流量上限」，即時截斷額外收費。
優先事項：學識「緊急煞掣」（而家即刻記住）
萬一你聽朝起身，發現 Email 收到 Budget Alert 話扣緊錢，你要識得即刻變返免費 Plan：

點樣降級：入去 Firebase Console 左邊齒輪 (設定) -> プロジェクトの設定 (Project Settings) -> 上面 Tab 揀 使用量と請求額 (Usage and billing) -> 詳細と設定 (Details & Settings) -> 撳 「プランを変更 (Modify Plan)」，將佢轉返做 Spark (無料) 就即刻截斷收費。

點樣鎖 Database：入 Realtime Database -> ルール (Rules)，將 read 同 write 改做 false，一秒踢走所有人。

方法 B：一秒鎖死 Database (Lockdown)
衝入去 Firebase 後台嘅 Realtime Database -> Rules，將所有讀寫權限變成 false：

JSON
{
  "rules": {
    ".read": false,
    ".write": false
  }
}
一 Save 呢段 Code，成個 Database 就會即刻變成「銅牆鐵壁」。駭客嘅 API Request 會全部被彈走（Permission Denied），而被拒絕嘅 Request 係唔會產生昂貴流量費嘅。

爆額時處理方法

⏬ 緊急煞掣：降級回 Spark (免費) Plan
萬一你想即刻截斷收費，退回 100 人連線限制，請跟住以下步驟：

進入 Firebase Console，點擊左邊選單齒輪 ⚙️ 「プロジェクトの設定」 (Project Settings)。

切換到上方選單嘅 「使用量と請求額」 (Usage and billing) Tab。

點擊 「詳細と設定」 (Details & Settings)。

撳右下角嘅 「プランを変更」 (Modify Plan)。

選擇 「Spark (無料)」 並確認。系統會即時截斷所有 Blaze 計費，恢復免費限制。

🔄 完美轉移指南 (金蟬脫殼大法)
步驟 A：搬 Database 數據 (極簡單)

喺現有嘅 Firebase 後台，入去 Realtime Database。

右上角有粒「三個點」嘅掣，撳 「JSON をエクスポート」 (Export JSON)，就可以將成個 Database 下載落你部電腦。

去新嘅 Firebase Account 開個新 Database，用同一粒掣撳 「JSON をインポート」 (Import JSON)，幾秒鐘就搬完！


步驟 B：轉移玩家帳號 (Firebase Auth)
因為玩家密碼經過高度加密，無法喺網頁後台直接下載，必須用終端機 (Terminal / PowerShell) 進行無損搬家：

準備環境：確保電腦有 Node.js，輸入指令安裝工具 npm install -g firebase-tools。

登入舊帳號：輸入 firebase login 登入你現時有 $125 帳單嘅 Google 帳號。

匯出資料：輸入 firebase auth:export accounts.json --format=json --project p-hall-v2，將所有玩家帳號密碼安全下載成 accounts.json。

匯入新場：登入新 Google 帳號後，輸入 firebase auth:import accounts.json --project [新Project-ID]，瞬間完成轉移。

其他firebase cli
firebase logout
firebase login
firebase login:add
firebase login:list
firebase login:use [你嘅另一個Email]

步驟 C：更新前端 Code (最重要)
當你搬好晒去新 Database 之後，你只需要打開你個 hall-shared.js，將入面嘅 firebaseConfig 換成新 Account 嗰條 API Key 同 URL，然後重新 Deploy 上 Vercel，全服玩家就會神不知鬼不覺咁連咗去新 Server。

步驟 D：API 金鑰安全設定 (網域白名單)
你記性非常好！開咗新 Firebase Project 後，系統會生成全新嘅 API Key。你必須將網域白名單加過去新 Server，否則駭客可以偷用你個 Database 刷 API：

登入新帳號嘅 Google Cloud Console。

左邊選單選擇 「API とサービス」 (APIs & Services) -> 「認証情報」 (Credentials)。

點擊名為 Browser key (auto created by Firebase) 嘅 API 金鑰。

喺 「アプリケーションの制限」 (Application restrictions) 選擇 「ウェブサイト」 (Websites)。

將你提供嘅清單 (*.itch.io/*, *hall-bice.vercel.app/*, http://localhost/* 等) 逐一加入並儲存。
